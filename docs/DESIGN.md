# 設計紀錄

這份記錄互動模型背後的理由。常數本身在 `src/engine/indoor-map.js` 開頭，改之前先讀這裡。

## 目標

使用者最常問的是「哪裡有空教室」。所以地圖先回答「哪一層空得多」，再回答「這層哪幾間空」：

- **地圖優先，清單為輔**。房間的位置本身就是資訊，顏色直接表示狀態（沒排課／60 分鐘內有課／有課／無課表資料）。
- 狀態一律寫「依課表」。有排課不代表正在使用，沒排課也不保證空著。

## 三層視圖與語意縮放

```
校園白模  ⇄  整棟（樓層總覽）  ⇄  單層
```

- **用縮放切換層級**，不用分頁：在整棟放大到某一層夠大就進入該層，縮小到底就退回整棟；校園白模放大到某棟填滿畫面就進入。
- **切換一律用飛行動畫**（`goToPose`），讓使用者知道自己到了哪一層級。飛行中忽略輸入，連觸控板的慣性滾動也一樣，避免在動畫中途誤觸發下一次切換。
- 點空白處退回上一層，這是很多人會自己發現的退出方式，保留。
- 高樓（例如先鋒 14 層）在總覽裡每層很小：總覽本身可以縮放、上下拖曳，看幾層的狀態而不必進去；
  門檻用「該層佔畫面高度的比例」判斷，不用寬度。
- 校園選取以畫面中心區域和置中程度加權，不用畫面佔比，否則大建物（綜科、科研）即使不在中間也會被選到。

## 相機

- 正交相機，姿態用 `heading`（畫面上方對應的地面方位）與 `tilt` 兩個角度描述，另加縮放與平移。
- **單層與整棟以主入口朝下**：`heading = π − 入口方位`，從入口走進去看的方向；校園白模固定北朝上。
- 自由度依層級收斂，避免迷路：校園可以平移、縮放、旋轉，俯仰鎖住；全樓層只能縮放和平移（旋轉、俯仰鎖住）；
  單層可以平移、縮放、旋轉（桌機用右鍵或 Shift 拖曳）。
- 單層的預設縮放刻意讓邊緣略微裁切，提示使用者畫面可以縮放；最小縮放留一點餘裕，不會在看清整層時誤退回整棟。

## 樓層與房間

- 整棟只建一次。切換視圖只調整每層的位置（總覽／單層／校園三套佈局）與透明度。
- 總覽的層距依視角計算，保證上下層不重疊。
- 單層時，上下鄰層只在飛行中畫成半透明，落地後只留外框，避免多邊形建物（綜科）辨識度下降。
- 房間的矮牆用 GIS 長邊重建成直角牆，不用多邊形簡化（會產生斜牆）。

## 標籤

- 標籤做碰撞迴避，依面積排優先順序。
- 樓梯、電梯、廁所等設施標籤依像素密度漸進出現，縮小時先隱藏。

## 資料

- 引擎不知道資料從哪來：`source`（`src/data/sources.js`）提供建物清單、各層多邊形與座標框架，座標換算只在 `project()` 一處。
- 教室範圍由排課資料決定：有課表紀錄的空間就是教室；GIS 標成教室但沒有課表的，顯示「無課表資料」。
- 狀態由宿主推進來（`setOccupancy`）：換一節課只重新上色，不重建幾何。
